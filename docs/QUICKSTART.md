# 五分钟上手

适用 v0.4.1。先用工程副本练习一次，再管理正在开发的工程。

## 1. 打开工程

从 [发行版](https://github.com/1300282202/stm32-git-manager/releases/tag/v0.4.1) 下载 Windows ZIP，完整解压，双击 `STM32Git.exe`。Git 需要已安装；Keil 仅在打开或编译工程时需要。

点击工程选择按钮，选择工程根目录。例如：

```text
MySTM32Project/
├─ Project.uvprojx
├─ User/
├─ hardware/
├─ Objects/
└─ Listings/
```

目录属于上层 Git 仓库时，应选择真正的仓库根目录。已有 `.git` 的工程直接读取现有历史；没有 Git 的工程会显示启用入口。

## 2. 保存第一个版本

1. 在 Keil 保存全部文件。
2. 在工具中为工程启用 Git，并设置本仓库的提交署名。
3. 打开忽略规则预览，确认只忽略编译输出和个人布局文件；源码、头文件、`.uvprojx` 应保留。
4. 在“当前修改”勾选要保存的文件，点击“加入版本”。
5. 填写说明，例如“完成 LED 点亮”，点击“预览并保存版本”，检查清单后确认。
6. 在“版本历史”确认新版本已经出现。

`your current branch ... does not have any commits yet` 表示还没有完成第一个提交。完成上面的保存后，历史才会出现。

## 3. 完成一次日常修改

在 Keil 修改并保存一个文件，回工具刷新、查看差异，加入本次版本、写说明并保存。每完成一个能解释清楚的小功能，就保存一次。未保存的 Keil 编辑不在磁盘上，工具无法读取。

## 4. 连接自己的 GitHub 仓库

1. 打开“远程同步”，点击“登录 GitHub”，在系统浏览器完成授权。
2. 用“网页新建 GitHub 仓库”打开 GitHub，创建自己的空仓库。首次连接已有本地工程时，不预建 README、许可证或 `.gitignore`，可避免两条初始历史冲突。
3. 复制新仓库的 HTTPS 地址，在工具中添加远程，名称通常填 `origin`。
4. 先保存至少一个本地版本，再预览推送，确认账号、地址和分支后上传。
5. 点击“打开在线仓库”，在网页确认文件和提交已经出现。

工具打开创建仓库的网页，由你在网页完成创建。不要把本项目的仓库地址当作你的工程远程。个人学习工程可按自己的分享需求选择 Private 或 Public。

## 5. 编译并归档

进入“构建与工程记录 → Keil 编译”，确认 Target、芯片和 Keil 位置，点“重新编译快照”，检查预览再开始。成功后查看日志、归档产物。它编译工程的独立文件快照，不覆盖原工程。

日常烧录继续在 Keil 操作。真正测试板卡后，再在工具里填写“手工上板结果”。
