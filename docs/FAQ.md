# 常见问题

## 第一次打开没有工程

这是公开版的正常状态。点击选择工程，选包含源码和 `.uvprojx` 的目录。公开版不携带开发者的最近工程或扫描预选路径。

## 没有提交记录 / main does not have any commits yet

仓库已初始化，但还没有第一个提交。在“当前修改”选文件、加入版本、填写说明并保存。保存后再查看历史。

## 只想保存到本地，必须登录 GitHub 吗

不需要。本地提交、分支、恢复、笔记和检查点都可离线使用。远程推送/获取才需要网络和相应仓库权限。

## 登录成功但推送失败

确认远程地址属于你的账号或你有写权限，且当前分支已有提交。首次连接已有本地历史时，优先创建空远程仓库。远程已有另一条历史或双方分叉时，工具不会强制覆盖；先获取并处理历史关系。不要将令牌粘贴到地址中。

## Git 没找到 / Git Credential Manager 不可用

安装 Git for Windows 并启用其凭据管理器，重新启动工具，使新 PATH 生效。工具不保存 GitHub 密码或令牌。SSH 连接的密钥和主机验证由系统 Git 管理。

## Keil 按 F7 能编译，工具却拒绝

先看预检提示。快照编译要求工程内相对依赖，拒绝工程外源码/包含目录、未解析变量、链接和已启用的用户构建脚本。请在 Keil 继续编译原工程，或在副本中整理依赖后再试，不必为通过预检直接改动正在工作的工程。

若预检通过但编译失败，确认 `UV4.exe` 路径、Target、对应编译器和设备支持包，查看完整日志。工具已适配旧 UV4 带空格 Target 的参数形式；其他 Keil/工具链组合仍需验证。超时或日志缺失不算编译通过。

## 编译成功为什么没有 HEX

Keil 工程可能没有开启 HEX 输出。在 Keil 的输出选项启用后再构建。只有本次真正生成且校验通过的产物会被列出，不沿用旧 HEX。

## 编译通过是否代表板子正常

不代表。工具不自动烧录。请在 Keil 烧录并实际测试，再填写手工上板结果。修改源码后旧结果仍保留，但不能代表当前快照已验证。

## 能直接管理其他 MCU / IDE 工程吗

一般 Git 操作可用于普通仓库，但 Keil 识别、忽略规则和编译有特定边界。本版主要验证 Windows / STM32 / Keil `.uvprojx`，没有 CubeIDE、IAR 等专用编译适配。

## GBK 源码和二进制怎么办

历史/差异会尽量展示文本，但内置冲突编辑和笔记编辑仅支持受限大小的 UTF-8。其他编码或二进制请使用外部编辑器，再回工具刷新、标记或保存版本，避免无意改变编码。

## 自动检查点会一直在后台运行吗

不会。默认关闭，需明确启用；仅在程序打开且选中该工程时工作。达到 20 个检查点暂停。本机备份不能替代异地备份。

## 更新后如何保留记录

关闭工具，备份程序旁整个 `data/`。新版解压到新目录，再按需迁入数据。工程自身的 `.git` 仍在工程目录中；不要删除它。源码 ZIP、检查点和固件来源归档都不能替代完整 Git 历史备份。

## Windows 提示未知发布者

当前发行包未签名。请只从本仓库 Releases 获取，使用页面提供的 SHA-256 核对下载文件，并按自己的设备管理要求决定是否运行。无需关闭系统安全设置。

## 完整支持 Git LFS 或所有 Git 命令吗

本版仅检测 LFS，不管理 LFS 内容过滤器/历史迁移；命令目录是帮助目录，不是任意 Git 命令执行器。完整支持范围见 [FEATURES.md](FEATURES.md)。
