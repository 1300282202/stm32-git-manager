# 使用说明

适用 v0.4.1，Windows x64。首次使用见 [五分钟上手](QUICKSTART.md)。

## 当前修改与历史

保存文件后刷新，选择文件查看工作区或暂存区差异。“加入版本”表示暂存，“保存版本”表示正式提交；没有勾选的文件不会被隐式加入。作者设置仅修改当前仓库。

“版本历史”可预览旧文件。恢复单文件前会预览并备份当前磁盘内容，再恢复工作区；原暂存选择保留，恢复后仍需决定是否提交。“恢复中心”可查看备份；后续编辑造成状态变化时，旧恢复预览会失效，需要重新检查。

工具不操作 Keil 中尚未保存的缓冲区。恢复、切换和合并后，Keil 如提示外部文件变化，请重新载入并编译。

## 分支与协作

- 新功能建议创建 `feature/功能名` 分支。切换前保持工作区干净，或先收起临时草稿。
- 合并先预览，冲突发生后到“解决冲突”选择一方、编辑最终结果，或在外部编辑器处理后标记。
- 内置冲突编辑支持 1 MB 内 UTF-8 文本；其他编码或二进制用外部工具处理。
- 普通提交可移植到当前分支。合并提交暂不支持移植。
- 临时草稿默认可包含未跟踪文件，忽略的编译输出不在草稿中。恢复前保持工作区干净；草稿归档后保留本地救援引用。
- 标签为提交命名，不自动证明编译或硬件正常。
- 独立工作目录共享历史、磁盘文件独立；移除入口拒绝强制删除含修改或未保存提交的目录。
- 源码 ZIP 导出指定提交，不包含未提交编辑、`.git` 历史、子模块对象或工程外依赖。

## 远程同步

GitHub 登录使用系统 Git Credential Manager。支持 HTTPS、SSH 和本机远程路径。地址中不得嵌入密码或令牌；SSH 密钥需自行配置。

“获取”更新远程跟踪信息；“拉取”仅支持快进；“推送”使用普通推送，不强制覆盖线上历史。分叉历史需先获取并在分支页处理。默认同步当前本地分支的远程同名分支。

推送前检查目标仓库、分支和待上传提交。已有其他工程的远程连接不会因打开本工具而自动改变。

## 专家工具箱

适合先在练习副本中使用：

| 功能 | 行为与边界 |
| --- | --- |
| 找回版本 | 从本机 reflog 选取记录，建立救援分支；对象已清理后不能保证找回 |
| 二分排错 | 手动选择正常/异常版本，在独立目录检出候选并测试；主工程采用 no-checkout；不自动运行测试脚本 |
| 重置 | 预览 soft/mixed/hard；操作前备份普通文件和索引，并建立救援分支；需要输入确认内容 |
| 清理 | 只清理用户逐项勾选的未跟踪普通文件，保留已跟踪文件和空目录；操作前备份 |
| 修改末次说明 | 要求干净且未出现在本机已知远程跟踪历史中；共享情况取决于最近获取结果 |
| 反向提交 | 新建提交抵消普通提交，保留原历史；不处理根提交或合并提交的反向撤销 |
| 仓库诊断 | 只读对象完整性和占用检查，不自动修复 |
| 离线历史包 | 导出并验证 `.bundle`；图形化导入尚未实现 |
| 命令目录 | 按本机 Git 生成命令与帮助目录；能查询帮助不等于可图形化执行全部参数 |

操作前整版备份最多 12000 个目录项、256 MB 普通文件，不处理链接、目录联接、特殊文件、嵌套仓库；不保存空目录、权限和 NTFS 附加数据流。导出磁盘文件不会自动恢复暂存选择；索引证据另存应用数据。重要工程仍应有异地备份。

## Keil 快照编译

1. 保存所有 Keil 编辑，进入“构建与工程记录 → Keil 编译”。
2. 确认 `.uvprojx`、Target、芯片和 `UV4.exe`，预览并开始重新编译。
3. 等待结果，检查错误和警告；默认超时 10 分钟，可取消本次任务。
4. 成功且输入快照校验通过后，再归档实际生成的产物。

先复制工程内普通文件，排除声明的输出/列表目录与个人窗口布局，再在系统临时短路径编译。不会把旧输出当成本次生成结果。通过同时要求成功退出码、零错误日志摘要和输入一致性；启动进程或出现旧 AXF 都不算通过。

预检会拒绝已启用的 BeforeMake/BeforeCompile/AfterMake 用户程序、工程外源码或 IncludePath、未解析变量、链接及嵌套仓库等不支持情况。快照上限 12000 项、256 MB，单个归档产物最多 64 MB。`.uvproj` 旧格式可有基础识别，但 D 编译入口以 `.uvprojx` 为范围。

旧 UV4 带空格 Target 已使用专用 Windows 参数格式适配。实际兼容性验证来自 Keil 5.18 / ARMCC 5.06，其他工具链需自行核对，预检通过也不保证编译器与设备包已安装。

编译记录包含来源提交或未提交快照、Target、日志、产物哈希、实际识别的编译器，以及当前文件是否仍匹配。改动文档也可能使快照匹配失效。编译与硬件验证独立；“手工上板结果”需要用户填写实际测试，本工具不烧录或自动判断硬件。

## 固件归档

成功记录中点“归档产物”，勾选 HEX/BIN/AXF/ELF，按需包含对应工程文件快照。归档会保存日志、来源清单、编译和手工验证状态、SHA-256 校验值。到“固件归档”可导出到普通空目录。

归档不含 Git 历史、Keil 安装、工具链和工程外依赖；不能保证在其他机器生成逐字节相同的固件。仅在 Keil 启用并实际生成 HEX 时才会列出 HEX。产物被改动时拒绝可验证归档或导出。

## Markdown 工程笔记

“工程笔记”中填工程内路径，例如 `docs/工程笔记.md`，读取或创建，编辑后点击“保存笔记到工程”。之后到“当前修改”决定是否提交。

支持基础标题、段落、列表、表格、代码块、粗体、行内代码、链接和本地图片。图片使用相对笔记的工程内路径，例如 `../images/wiring.png`，支持 PNG/JPEG/GIF/WebP，单张最多 3 MB。远程图片不自动加载，原始 HTML 作为文字显示；普通链接仅允许不含账号密码的 HTTPS 地址。

笔记须为 1 MB 内 UTF-8；保留既有 BOM。保存前校验外部修改并备份旧内容。编辑草稿在本机浏览器存储中，点击保存才写工程。预览是常用语法子集。

## 本地检查点与扩展

“立即保存检查点”保存普通磁盘文件及索引证据，不创建正式提交或分支；导出到空目录查看。自动检查点默认关闭，用户启用后，仅在程序打开、该工程被选中且无写操作时运行；内容不变则跳过，最多 20 个，到上限暂停。轮询最长额外约 30 秒。旧检查点可以移到系统回收站，处理的是应用副本。

“扩展与迁移”仅检测 LFS 版本、按文件类型生成可编辑的提交说明草稿，以及导出迁移 JSON 检查清单。没有在线 AI、LFS 历史迁移或完整工程迁移包。

## 数据与升级

便携包默认数据在程序旁 `data/`；源码运行在仓库根 `data/`。可用 `STM32_DATA_DIR` 环境变量指定可写目录。构建与归档在 `data/engineering`，整版备份/检查点在 `data/expert-backups`。

升级时先关闭程序、备份整个 `data/`，将新版解压到新目录，再按需迁入数据；不要覆盖正在使用的目录。移动程序或工程前保存 Keil 编辑并关闭相关任务。避免多个 Git 客户端同时写同一工程。
